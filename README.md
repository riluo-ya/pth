# PTH —— Phigros Tool Hub

**PTH（Phigros Tool Hub，Phigros 工具枢纽）** 是一个 Phigros 工具集合站：主页是导航中心，
下挂谱面下载站、答题验证、谱面工坊、蓝奏云网盘索引与 SIGNAL 演出工具。
谱面、曲绘、音频统一从上游公开仓库拉取，本地只做索引、筛选与打包。

- 在线地址：https://phth.cc.cd/
- GitHub 仓库：`riluo-ya/pth`
- 技术栈：Vite + React + TypeScript（下载器）、原生 HTML/JS（导航页与各入口页）

> **更名记录**：项目原名 PCD（Phigros Chart Downloader），因早已超出「下载器」范畴，
> 现更名为 **PTH / Phigros Tool Hub**。域名由 `pcd.bot.cd` 换成 `phth.cc.cd`，
> 仓库由 `riluo-ya/pcd` 换成 `riluo-ya/pth`。
> 数据文件名 `pcd.data` 是历史沿用，为避免破坏读取逻辑与已发布链接，**保持原名不改**；
> 站内所有 CDN / Raw 回退地址、分享卡片二维码、卡片署名均已同步到新仓库与新域名。
> 上游项目 `swordalt/phigros-chart-downloader` 是另一仓库，链接保持不变。

## 页面说明

| 页面 | 作用 |
|---|---|
| `/` | 导航中心（主页），展示各工具入口 |
| `/quiz/` | 从加密题库随机抽 5 题，全部答对后签发凭证，跳转目标页 |
| `/download/` | 谱面下载站（Vite 构建产物） |
| `/pmth/` | Phigros Chart Studio 谱面工坊：导入谱面，应用规则后导出 |
| `/philzy/` | 蓝奏云网盘索引 |
| `/signal/` | SIGNAL 演出工具：编辑选项与数字，预览动画并导出 MP4 / PNG 帧序列 / GIF（**第三方项目站点接入**） |

谱面工坊处理用户上传的谱面文件（`.json` / `.zip` / `.pez`），
应用替换规则与特性后导出。**输出格式跟随输入**：导入 `.pez` 就导出 `.pez`
（`.pez` 本质是改了扩展名的 zip，Phira 靠扩展名识别，写成 `.zip` 就认不出来了）。

> 谱面工坊导出的是谱面 JSON，需要放进 Phira 能识别的容器里。`.pez` 就是
> 那个容器 —— 本质是把 `info.txt` + 谱面 JSON + 曲绘 + 音频打包后改了扩展名
> 的 zip。Phira 靠扩展名判断能不能导入，所以扩展名写错会直接导致导入失败。

> 导入时的格式会一路记在每张谱面上（`ext` 字段），导出时按它还原，
> 不会因为文件名里没有扩展名就掉回 `.json`。

**支持压缩包套压缩包**：上传下载站导出的那种「按歌曲分目录、每难度一个
`.pez`」的压缩包时，会自动递归展开成多张谱面，并按歌曲名与难度编号：

```
上传 songs.zip
  → DESTRUCTION_3,2,1/  ×  EZ / HD / IN / AT
  → Glaciaxion/         ×  EZ / HD / IN
  → 展开为 7 张，按「歌曲名 · 难度」逐条列出
```

也兼容「原始资源平铺」格式（`曲名/charts/*.json`），以及两者混合的目录。
曲名与难度优先从包内 `info.txt` 的 `Name` / `Level` 行读取，读不到才按文件名猜。

批量上传多张谱面时，可勾选「分别处理所有勾选谱面，打包成一个压缩包」，
得到内含各难度独立谱面包、且按歌曲分目录的压缩包；
不勾选则只处理主谱面，或走「整合」混排成一张。

**噪域（blockArea）**

Phigros 新版在谱面里新增了 `blockAreaList`（噪域）：按两个对角坐标定义矩形区域，
在 `enableTime ~ disableTime` 期间遮挡屏幕；`isSubtract` 为真是「减算」，即挖洞。

工坊在「整合」面板提供噪域下拉，四种处理方式：

| 选项 | 行为 |
|---|---|
| 保留原样 | 不动，整合时随主谱面带过去 |
| 合并并去重 | 所有谱面的噪域合进来，按「坐标 + 四时间点 + isSubtract」去重 |
| 只保留主谱面 | 其他难度的噪域丢弃 |
| 删除所有噪域 | 输出干净谱面 |

谱面列表会显示每张的噪域数量，下拉下方显示构成（遮挡 / 挖洞各多少）与覆盖时间跨度。

「谱面统计」卡片底部还有一块噪域概览：总数、遮挡/挖洞的构成条、
以及覆盖的时间跨度（m:ss）。没有噪域时显示「当前谱面没有噪域」。

**界面控件的一致性**

工坊里的下拉与复选框都是自绘的，不用浏览器原生控件 —— 原生 select 在手机端会
弹出系统控件、桌面端各浏览器渲染也不一致，深色界面里很跳；原生 checkbox 是白底
方块，同样违和。

自绘下拉保留原生 `select` 作为数据源（加 `.cmb-src` 隐藏），只替换外观 ——
读 `.value`、监听 `change` 的既有代码都不用改。禁用项（`option.disabled`，
规则行靠它避免 `from == to` 的无意义映射）在自绘下拉里同样不可点。

面板里的行、提示、输入框统一用 `.mo-row` / `.mo-tip` / `.mo-field`，
色值全部走 CSS 变量。这些样式原先挂在 `.merge-opts` 前缀下，
导致批量面板用同样的类名却拿不到样式、只能靠内联 style 硬凑另一套颜色。

> 噪域需要 `formatVersion >= 3`。若主谱面是老版本而整合时合并进了噪域，
> 工坊会自动把版本升到 3 —— 否则版本号还是旧值，Phira 认不出 `blockAreaList`。
>
> ⚠️ 官方文档把动画字段写成 `rotateEventsList` / `moveEventsList` / `scaleEventsList`，
> 但实谱里**没有 `List` 后缀**（是 `rotateEvents` / `moveEvents` / `scaleEvents`）。
> 照文档写会取到 `undefined`。目前只做搬运/去重/删除不读事件，
> 将来若要编辑噪域动画，务必用无后缀的名字。

**info.txt 与 info.yml 会一起改**

两个文件作用相同（yml 是下载站额外附带的等价描述文件），
所以难度标识会同步写入两者，不会只改一个导致包内信息自相矛盾。
查找文件名大小写不敏感，子目录内的也能找到。

**输出命名：歌曲名 + 难度标识**

```
Exoplanetary Mirage_AT.pez
```

标识规则：

| 标识 | 含义 |
|---|---|
| `ALL TAP` | 全部转为 Tap |
| `ALL DRAG` | 全部转为 Drag |
| `ALL HOLD` | 全部转为 Hold |
| `ALL FLICK` | 全部转为 Flick |
| `RANDOM` | 随机 |
| `MIXTURE` | 整合混排 |
| `AX` | 自定义类型映射 |
| `IN` 等 | 未做转换时，保留谱面原本的难度 |

文件名与包内 `info.txt` / `info.yml` 的 `Level` 字段用同一套标识，
全部大写。整合统一记 `MIXTURE`，不再把参与难度拼进去（如 `MIX-EZHDINAT`）。

标识含空格（如 `ALL TAP`），所以替换时按「`Lv.` 及之后」切分、
只改它前面的部分 —— 对已处理过的文件再跑一次不会叠成 `ALL ALL TAP`。

答题页的几个机制：

- **随机抽题**：每轮从题库随机抽 5 题并打乱选项顺序
- **会话倒计时**：5 分钟未提交会自动换一批题
- **连续答错硬锁**：累计答错 5 次锁 **5 分钟**。冻结期间页面只显示倒计时、
  状态说明与管理员密码框，**不提供任何自助清除入口**；冻结判断优先于凭证检查，
  锁定期不会显示凭证横幅、也不会加载题目
- **解除方式只有两种**：等倒计时结束自动恢复，或输入管理员密码
  （`MD5('riluoya')`）提前解除。错误页的「重新加载」和下载站的「清除缓存」
  都**不会**清掉冻结状态
- **云端时间锚点**：只在触发锁定的那一刻请求一次同源响应的 `Date` 头
  （`HEAD /quiz/?_t=…`），作为服务器时间锚点。正常访问导航页、下载站或未锁定的
  答题页**不会发任何时间请求**。`Date` 头是服务器生成的 GMT 绝对时间，
  解析不依赖本地时钟
- **解封双条件**：① 用 `performance.now()` 单调累计的本页等待 ≥ 5 分钟；
  ② 满 5 分钟时再联网取一次云端时间，确认相对锚点确实过了 5 分钟。
  系统时间（`Date.now()`）**完全不参与判定**，往前调、往后调、中途调都无效
- **断网一直锁**：取不到云端时间就不开始计时 / 不放行，每 10 秒重试，
  直到联网成功。本站题库、曲库索引、曲绘与音频本来就都要联网，
  离线根本用不了，因此不会误伤正常用户
- **必须待在本页**：关闭页面期间不累计，回来接着算；刷新页面不重置。
  锁定界面已写明这一点，避免退出去等 5 分钟回来发现还锁着。
  状态存在 `pth_freeze_state`，后台标签页被节流时按真实经过时间补上，不会少算
- 边界：前端存 localStorage 的门槛挡不住 DevTools 直接改存储、覆盖 `fetch`
  或换浏览器——这是门槛不是安全边界。这里保证的是**页面上不给绕过按钮**、
  **改系统时间无效**、**断网不放行**，且不在界面里提示绕过方式

## Token 鉴权机制

所有页面共用同一套凭证：

1. **答题页**：答对后生成 `access_token` 存入 localStorage，格式为 `base64("时间戳|随机uid|djb2签名")`，**有效期 12 小时**。
2. **导航中心 / 网盘 / 工坊**：加载时校验凭证，无效则显示「访问受限」弹窗，可返回答题页。
3. **下载器**：由 `AuthGate` 组件校验，无效时显示全屏受限页。

### 验证后返回原页面

被拦截时，页面把当前地址通过 `?return_to=` 传给答题页，答完自动跳回，
而不是一律落到导航中心。典型场景：

```
扫码打开 /download/?song=xxx → 凭证失效被拦
  → /quiz/?return_to=...%3Fsong%3Dxxx
  → 答对 → 回到 /download/?song=xxx（自动选中那首歌）
```

**例外**：下载站只在带 `?song=` 的分享链接时才原路返回。直接访问下载站
首页被拦时，答完题会去导航中心 —— 从那里能进下载器，不会停在空白曲库上。
其他受保护页面无论有没有参数都照常回跳。

安全与可靠性上的几条约束：

- **只看当前链接的 `?return_to=`，不读写任何本地存储**。地址栏里没有就当作没有，不会出现残留的跳转目标。
- **白名单校验**：只接受同源且位于白名单子目录（`/download` / `/pmth` / `/philzy` / `/signal`）或站点根（导航页）的返回地址，答题页自身排除在外，避免「弹回 → 答完 → 再弹回」死循环。
  白名单按**路径前缀**匹配：子目录页的最后一段是空串或 `index.html`，只比文件名会把 `/pmth/` 和 `/download/` 都误判成站点根。
- 新增受保护页面时，需同步答题页里的 `ALLOWED_PREFIXES`。

## 谱面下载器

### 布局

与上游 `swordalt/phigros-chart-downloader` 一致，手机与桌面是**两套组件树**（由 `useIsMobile` 判断，
断点为 768px），不是靠 CSS 响应式硬凑。

- **桌面（≥768px）**：顶栏 + 左侧 340px 常驻歌曲列表 + 右侧工作区 + 页脚，两栏各自内部滚动。
- **手机（<768px）**：`MobileLayout`
  - `MobileLibrary`：曲库占满整屏，顶部 52px 标题栏与筛选 chips，底部常驻搜索框
  - `MobileSongView`：点歌后从右侧推入的全屏页面，顶部曲绘 hero、左上角返回、底部常驻导出栏
  - `BottomSheet`：底部抽屉，承载菜单（设置 / 加速源 / FAQ / 关于 / 返回导航）与筛选面板
  - 推入时写入 history，系统返回手势可回到列表

手机上筛选沿用本站的完整条件（难度 / 定数 / 谱师 / 曲师），面板与桌面端共用 `SongFilterPanel`。
手机端列表页顶部与抽屉菜单里都有返回 `/`（导航中心）的入口，桌面顶栏的「返回导航」常驻显示。

### 选歌与筛选

选歌按钮右侧的漏斗图标可按 **难度 / 谱师 / 曲师** 筛选曲库：

- **必须含难度**：EZ / HD / IN / AT 可多选，需同时满足
- **指定定数**：精确的定数，可带小数也可不带（`17`、`17.6`、`15.3` 都行）；
  多个用逗号分隔（`15.3, 17.6`），之间是「或」的关系
- **定数区间**：任一难度落在区间内即命中
- **谱师 / 曲师**：可输入也可选择，输入实时过滤候选，聚焦或点箭头展开列表

> 「指定定数」与「定数区间」可同时填写，此时需要两者都满足（是「且」不是「或」）。
> 填了互相矛盾的条件会得到空结果 —— 这是预期行为，不是 bug。
>
> 定数比较带 0.05 的容差：上游同一数值可能写成 `17.6` 或 `17.60`，
> 直接用 `===` 比较浮点会因精度问题漏掉。0.05 远小于定数最小间隔 0.1，不会误判。

按钮上有角标显示生效了几项筛选；下拉顶部显示当前筛选条件，可一键清除。
筛选与关键词搜索是叠加关系（先在筛选结果里搜）。

几个实现上的取舍：

> 谱师/曲师用自绘组合框而非原生 `<select>` —— 浏览器自己画的下拉面板
> 和站点深色风格对不上。设置里的「导出图片类型」同理改成了分段控件。

> 输入时做「包含」匹配方便找人，真正生效的筛选仍用**完全匹配**，
> 保证选中的谱师精确对应一个人。打了一半就失焦会回退到上一个有效值，
> 不会留下「筛不出东西但看不出原因」的状态。

> 作品数按「歌曲」计而非「难度条目」计 —— 同一首歌多个难度都是同一位谱师
> 时只算一首，避免下拉显示 37 却只筛出 24 首。

### 难度与导出

导出格式可在设置里选 `.pez`（Phira 原生）或 `.zip`，
可选附带 `info.yml`。

**未指定难度时导出该曲全部难度**：每个难度一个包，再统一打包成一个
压缩包，文件名形如 `曲名_all-difficulties.zip`，解压后逐个导入即可。
指定了难度才只导那一个。

曲目实际拥有的难度以难度表为准 —— 缺列、空串、`—`、`?`、`∅`、`0`
都视为「不存在」。全库 320 首中 271 首没有 AT，这些曲子不会凭空多出 AT 行。

### 批量下载

在设置里开启「批量下载模式」后，主界面换成批量面板：先筛选，再勾选，最后打包。

**筛选条件**

| 分类 | 条件 |
|---|---|
| 基础 | 关键词（曲名 / ID / 作曲家 / 谱师）、作曲家包含、谱师包含 |
| 定数 | 精确值（逗号分隔）+ 区间筛选，可作用于「任一难度 / 最高难度 / 指定难度」 |
| 难度 | 必须含哪些难度（可多选） |
| 安全 | 排除含黑名单谱面的曲目（默认开启） |
| 谱面数据 | BPM、时长、物量、判定线（需解析谱面，勾选后才启用） |

**导出难度**

默认导出每首歌的**全部难度**。只想练某个难度时可单独指定，
歌曲没有的难度自动跳过；若指定的难度该曲一个都没有，退回它实际拥有的
（不会导出空包）。列表每行显示该曲拥有的全部难度徽章，一眼看清会下几个。

**打包方式**

默认「每难度独立谱面包」，产出的结构是：

```
曲名/
├── 曲名_EZ.pez
├── 曲名_HD.pez
├── 曲名_IN.pez
└── 曲名_AT.pez
```

每个难度一个可直接导入 Phira 的谱面包，解压后逐个导入即可。
代价是同一份曲绘/音频会在每个难度的包里各存一份，体积较大。

想省体积可切到「原始资源平铺」：曲绘与音频各存一份，
谱面 JSON 放在 `charts/` 目录，但需自行组装才能导入。

两种模式下资源都**每首歌只下载一次**再复用给所有难度，
请求数不会因为打包方式而增加。若某首歌的曲绘或音频下载失败，
该曲会退化为只放谱面 JSON，不至于整首消失。

**其他**

- 曲目列表可逐条勾选或「全选筛选结果」；被筛掉的曲目自动移出选中集合
- 支持分批打包（默认每包 50 首），避免单个巨型压缩包
- 开始前显示摘要：多少首、几个包、约多少次请求、预计耗时（默认间隔 0.6 秒）
- 含黑名单谱面时开始前统一提示确认，而不是逐首弹窗
- 结束后列出失败文件，可「仅重试失败的曲目」

**请求量与限流**

每首歌的请求数 = 非谱面资源（每难度独立包模式为 1 张曲绘 + 音频，
平铺模式为 3 张曲绘 + 音频）+ 实际难度数。
因为不再盲目试 4 个难度，全库谱面请求从 1280 次降到 1009 次。

GitHub 有非官方限流（约 5000 次/小时），建议保留 0.5 秒以上的歌曲间延迟。

### 常见问题（外部 JSON）

问答内容来自外部 `Download/public/faq.json`，改完推送即可生效，不用重新构建 —— 与更新日志同一套机制。

数据源按优先级依次尝试：本站 → jsDelivr CDN → GitHub Raw。全部失败时回退到 `faqData.ts` 里打包的内置问答，
保证「常见问题」永远不会空白。弹窗底部显示当前来源，失败时给出「重试」按钮。

文件格式与数据管理器导出的结构一致：

```json
{
  "notice": "置顶公告，不需要就留空",
  "faqs": [
    {
      "question": "问题？",
      "answer": "答案，支持换行",
      "links": [ { "text": "链接文字", "url": "https://…" } ]
    }
  ]
}
```

- `links` 可选且可多条，在弹窗里渲染成一张张小卡片
- 同时写 `link` 与 `links` 时以 `links` 为准（单条 `link` 用于兼容旧解析）
- 地址可省略协议（自动补 `https://`），`javascript:` / `data:` 等非 http(s) 协议会被丢弃
- 答案支持换行与安全的排版 HTML，`<script>`、`onerror=` 等一律转义

### 弹窗滚动的两个前提

手机端整屏弹窗（设置 / 关于 / 常见问题 / 分享卡片）能滚动，需要同时满足两点，缺一不可：

1. **面板必须是 flex 列**（`flex flex-col`）—— 内容区靠 `flex-1 min-h-0` 撑开。
   少了这一项，`flex-1` 完全失效，而面板是 `overflow-hidden` + 固定高度，
   内容溢出会被直接裁掉，**既看不到也滚不动**，很容易被误判成布局 bug。
2. **高度单位带 `vh` 兜底** —— 见下一节。

新增弹窗时照抄现有结构即可。测试里对每个弹窗的 `flex flex-col` 都有断言。

### 移动端高度单位兼容（`dvh`）

页面外壳与弹窗用整屏高度。这里没有直接写 `dvh`，而是用 `index.css` 里的三个兼容类：

| 类 | 用途 |
|---|---|
| `.h-app-shell` | 页面外壳（`100vh` 打底，`100dvh` 覆盖） |
| `.h-dialog-panel` | 手机端整屏弹窗（`calc(100vh - 10px)` / `calc(100dvh - 10px)`） |
| `.max-h-sheet` | 底部抽屉（`86vh` / `86dvh`） |

iOS Safari 15.4 以下、旧版 Android WebView 和部分 App 内置浏览器不认识 `dvh`，
**整条 `height` 声明会被丢弃**（不是取近似值）。配合外层的 `overflow-hidden`，
表现就是「只看到一截、怎么滑都滑不动」——很容易被误判成滚动或布局 bug。

改成新增单位后，如果哪天又直接写回 `dvh`，Tailwind 只扫描源码里出现过的类，
旧类名的样式不会被生成，测试里对高度的断言会立刻失败。
### 加速源

可在界面切换 5 个源：GitHub 直连、jsDelivr CDN、gcore CDN、
ghproxy.net、gh-proxy.com。国内推荐 jsDelivr 或 gcore。

索引类数据（版本 / 曲目表 / 难度表）会带 CDN 版本号参数，
点「清除缓存」时递增版本号以强制 CDN 回源 —— 否则上游更新了，
CDN 边缘节点仍会返回旧内容。

「清除缓存」会注销 Service Worker、清空 Cache Storage / IndexedDB /
sessionStorage，但**保留**登录凭证、已选加速源与 CDN 版本号，
避免清完掉回 GitHub 直连或需要重新答题。

### 导出能力

三种格式都在浏览器本地逐帧渲染，不上传任何数据：

| 格式 | 说明 |
|---|---|
| MP4 | H.264 视频，可选 AAC 音轨；1080p / 2K / 4K，30–165 FPS |
| PNG ZIP | 帧序列 + `manifest.json`，1–165 FPS，单次最多 5000 帧 |
| GIF | 彩色动画，四档压缩，最高 720p |

MP4 封装使用 `vendor/mediabunny.js`（Mediabunny 1.62.0 + AAC 编码器，MPL-2.0），
导出前会检查 WebCodecs H.264、Web Worker、WebAssembly 与 Web Audio 能力，
不满足时明确报错而不是静默降规格。2K / 4K 直接按目标分辨率创建 Canvas，
不由 1080p 放大生成。

⚠️ **MP4 导出需要 HTTPS 或 localhost 安全环境**（浏览器对 WebCodecs 的限制，
前端无法绕过）。用 `http://` 访问时，PNG 帧序列与 GIF 导出仍可正常使用。
高分辨率、高帧率、复杂图层或长时间动画会显著增加内存与编码负载。

除导出外还提供「高级功能」面板：关键帧时间轴、自定义字体、文字与图片图层、
音频编辑与节拍同步、主题库、模板库、分享链接、批量导出队列，以及
1:1 / 9:16 画幅与多种展示模式。逐项说明见更新日志的 `signal` 栏。

### 弹窗与提示

全站使用自绘弹窗，不用 `window.alert` / `window.confirm` —— 浏览器原生弹窗是
系统控件，跟深色界面完全不搭，手机上还会卡住整个页面。

自绘版本位于 `Download/src/components/ui/Dialog.tsx`，提供：

- `NoticeDialog` —— 信息 / 警告 / 错误三种 tone，顶部一条对应色的细线
- `ConfirmDialog` —— 确认框（批量下载前的黑名单预检用它）
- `ErrorBody` —— 正文 + 可折叠的技术细节，取代「请查看控制台」
- `DialogFrame` / `DialogHeader` / `Eyebrow` / `Button` —— 容器与排版件

错误与警告**不会**因点击遮罩关闭，避免误触丢掉提示；Escape 始终可关。

### 分享卡片的两个已知坑

1. **曲绘加载必须带超时**。
   `<img>` 只有 `onload` / `onerror`，请求挂起时（加速源不可达但连接未断）
   两个回调都不触发，Promise 永远 pending，卡片就永远停在「正在生成卡片…」。
   现在每个源最多等 8 秒，超时即按失败处理，用占位图继续生成。
2. **生成失败要可见**。
   渲染异常时以前只是静默回到初始态，界面一片空白。现在会显示原因与重试按钮。

## 注意事项

1. **通过网站地址访问**（`http://` 或 `https://` 均可），不要直接双击打开 ——

4. **上游限流**：批量下载大量曲目时请保留歌曲间延迟，避免触发限流

5. **谱面版权**：谱面与曲绘版权归各自作者与 Phigros 官方所有，
   本项目仅做索引与下载，请勿用于商业用途。

6. **密钥类信息不要硬编码进仓库**：管理员密码、题库解密口令、统计用的
   Webhook 地址等敏感值不应提交到公开仓库。如需更换，请同步修改
   对应页面与源码中的引用处，并把旧值作废。

`data.html`（数据编辑后台）已删除；三个 `.data` 文件与两份 JSON 统一放进 `data/`。

### 更新日志怎么管

**只有 `data/changelog.json` 一个文件，包含全部日志**，改完推送即生效，不用重新构建。

结构是「**一天 = 一组，组里按栏目分栏**」。一天有四个固定栏目：
下载站 / 谱面工坊 / SIGNAL / **其他**，想填哪个就填哪个，
**没填的就是空的** —— 该栏目这一天不会有任何内容：

```json
{
  "notice": "置顶公告，不需要就删掉或留空",
  "logs": [
    {
      "date": "2026-11-13",
      "pages": {
        "download": "修复分享卡片曲绘不显示\n- 多加速源并行取图\n- 特殊字符正确编码",
        "pmth":     "谱面工坊\n- 适配新的谱面结构",
        "signal":   "",
        "other":    ""
      }
    }
  ]
}
```

- `logs[]` 里**每个元素就是一天**，字段只有 `date` 和 `pages`。
- `pages` 固定四个键：`download` / `pmth` / `signal` / `other`。填了才有内容，留空（或写 `""`）就是空的。
- **`other` 是「其他 / 站点级」栏目**：写不属于某个子页面的更新 —— 导航页改版、域名更替、
  目录结构调整、全站公告、答题页或蓝奏云本身的改动等。它**没有对应子页面，只在导航页 /
  蓝奏云（全部视图）里出现**，下载站 / 工坊 / SIGNAL 不会带出这段内容。
- 每一栏的正文用 `\n` 换行，一行 = 一个列表项；也可直接写安全的排版 HTML。
- 导航页 / 蓝奏云会显示这一天里**所有非空分栏**，每栏各自标注栏目名（「其他」是紫色标签）；
  其余页面只取自己那一栏，**自己那栏没填则这一整天都不出现**。
- 某页面所有天都没内容 → 显示「**暂无信息**」。目前 `other` 只在导航页 / 蓝奏云可见；
  `signal` 在 2026-11-14 补了一条组件修复记录，所以 SIGNAL 页现在有 1 天内容。
  想让它继续空着，把那天 `pages.signal` 清空即可，代码不用动。

| 栏目 | 对应页面 / 用途 |
|---|---|
| `download` | **只写 `/download/` 子目录里那个下载站项目本身** |
| `pmth` | 谱面工坊 |
| `signal` | SIGNAL 演出工具 |
| `other` | 其他 / 站点级（仅导航页与蓝奏云可见） |

**栏目归属按代码所在目录算，别混**：`download` 只放 `Download/` 源码和 `/download/`
页面自己的改动（曲库、导出、分享卡片、设置、关于弹窗等）。答题页的安全机制、
`data/pth-crypto.js` 这类跨页面兼容层、原生页面的日志组件、站点改名 / 域名 /
目录 / CI / 文档等全站性内容，一律写进 `other`。判断不了就放 `other`，
宁可让导航页多显示一段，也别让下载站「关于」里冒出跟自己无关的条目。

各页面的显示方式（**只有导航页与蓝奏云显示全部，其余各页只看自己那一栏**）：

- 导航页：卡片区下方的常驻区块，**显示全部**
- 蓝奏云（philzy）：右下角按钮 → **居中弹窗**，**显示全部**
- 下载站：**不显示浮动按钮**，顶栏「关于」弹窗里已内置「更新日志」区块（`useChangelog(..., 'download')`），**只看 download**
- 谱面工坊：右下角按钮 → **居中弹窗**，**只看 pmth**
- SIGNAL：右下角按钮 → **居中弹窗**，**只看 signal**
- 答题页：**不显示更新日志**（已移除）

想给某栏目补日志，就在对应日期的 `pages` 里把那一栏填上；没有这一天就新建一天，
其余栏目留空即可，不用改代码。数据管理工具（`pth_数据管理工具.html`，独立文件，不在仓库里）
是一天一张卡、卡里四个分栏输入框（含「其他」），支持「已填 N/4 栏」提示、
「其他」栏目预览与按栏目模拟线上筛选结果。

兼容：早期平铺格式（`date` / `scope` / `content`）与 `contentByScope` 分段格式仍可读取，
导入时会自动按日期归并进对应分栏，线上若还缓存着旧 JSON 也不会显示异常。

弹窗点遮罩空白处、右上角 ×、Esc 都能关，打开时锁住页面滚动。蓝奏云 / 谱面工坊 /
SIGNAL 统一用浮动按钮 + 居中弹窗（强调色各不相同），导航页保持内嵌区块以填补卡片区下方的空白；
下载站与答题页不引浮动按钮。引脚本的页面共用 `data/changelog-widget.js`，
数据依次尝试「脚本同目录」→ 根路径 `/data/` → jsDelivr → gcore → GitHub Raw。

### 更新日志不显示时怎么排查

四个原生页面（导航页 / 蓝奏云 / 工坊 / SIGNAL）的日志完全依赖 `data/changelog-widget.js`
去读 `data/changelog.json`；下载站另有打包在 JS 里的内置兜底日志，所以**在线 JSON 挂掉时
往往只有下载站看起来正常**，这是判断问题方向的关键线索。

按顺序检查：

1. 打开 `https://phth.cc.cd/data/changelog.json`，应能看到 `"pages"` 字段（含 `other`）。
   404 或还是旧的 `scope` / `content` 结构 → 说明 `data/` 没推上去或推的是旧包。
2. 打开 `https://phth.cc.cd/data/changelog-widget.js`，搜索 `normalizeDay`。
   搜不到 → 线上还是旧版组件，读不懂新的 `pages` 结构。
3. 浏览器 DevTools 的 Console 会打印 `[changelog] widget v… | scope=…` 和
   `[changelog] 命中数据源 N：…`；若全是「源 N 失败」，说明数据地址不通。
4. 组件现在会在**所有数据源都失败**时显示黄色错误卡片和「重新加载」按钮，
   不再伪装成「暂无信息」；「暂无信息」只代表该栏目确实没填内容。

四个页面引用组件时带了 `?v=20261113e` 版本号。**以后每次修改 `data/changelog-widget.js`，
都要同时把这四个 `?v=` 一起改掉**（以及文件内的 `WIDGET_VERSION`），
否则浏览器 / CDN 会继续用缓存里的旧组件，与新 JSON 结构错配。
CI 的 `Verify dist layout` 现在会在 `data/changelog-widget.js` 等必要文件缺失时直接失败。

### 用 http 访问也能正常用

浏览器只在**安全上下文**（`https://`、`localhost`、`file:`）里开放 `crypto.subtle`，
而导航页 / 答题页 / 蓝奏云页要用它解密 `data/` 下的 `.data` 文件。以前用 `http://`
打开时，答题页会直接报「Web Crypto API 不可用」，拿不到凭证，下载站跟着被 `AuthGate`
挡住 —— 看起来像是下载站坏了，其实是答题页没解开题库。

现在引入了 **`data/pth-crypto.js`** 兼容层：

- **https**：仍走原生 Web Crypto，速度不变
- **http**：浏览器不给 `crypto.subtle`，自动切到文件自带的纯 JS 实现
  （PBKDF2-HMAC-SHA256 + AES-256-GCM），**`.data` 文件格式完全不用改**
- 三个页面只需在 `</head>` 前引一行脚本，`decryptData` 统一调 `PthCrypto.decrypt()`
- 纯 JS 首次派生密钥约 **1~2 秒**（手机可能更久），结果缓存在 `sessionStorage`，
  之后同标签页内再进任何页面都是秒开；页面加载时会自动显示一句「首次解密数据约需 1~2 秒」
- `checkEnvironment()` 不再把「没有 subtle」当错误，只保留 `file://` 的提示

三个页面的引用都用**相对路径**（根页面 `./data/`、`quiz/` 与 `philzy/` 用 `../data/`），
自定义域名没生效、走 `xxx.github.io/pth/` 子路径时同样能命中。

**仍未绕过的浏览器限制**：`http` 下 `navigator.clipboard` 通常不可用，分享卡片点
「复制图片」会弹出提示，改用「下载图片」或长按保存即可 —— 这是浏览器行为，前端改不了。
另外 http 是明文传输，证书能签下来还是建议勾 **Enforce HTTPS**。

独立的数据管理工具（`pth_数据管理工具.html`）仍建议通过 `http://localhost:...` 打开；
直接双击用 `file://` 打开时，浏览器同样不开放 Web Crypto，题库加解密会失效。

### 本地与部署

```bash
cd Download
npm install
npm run build     # vite build 产出 dist/download/，copy-static.mjs 补齐其余部分
npm run preview   # 零依赖整站预览：http://localhost:4173/
```

`npm run build` 生成的 `dist/` 就是线上完整站点，GitHub Actions 走同一条命令，
`publish_dir: ./dist`。本地开发 `npm run dev` 只起下载站（3000 端口），
日志组件会自动回退到 CDN 取数据。

### 路径约定

页面之间一律用绝对路径（`/`、`/quiz/`、`/download/`、`/pmth/`、`/philzy/`、`/signal/`）。
答题页 `ALLOWED_PREFIXES` 是回跳白名单，新增受保护页面时记得补进去；
**不要**把 `/quiz` 加进去，否则会出现「弹回 → 答完 → 再弹回」死循环。
